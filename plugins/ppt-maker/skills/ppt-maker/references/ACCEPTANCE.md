# 验收

**机器校验通过 ≠ 验收通过。** 这份文件的全部意义在于把这两件事分开。

## 机器管什么

`npm run check` = typecheck → validate → export → verify:geometry。

| 检查 | 能证明 | 证明不了 |
|---|---|---|
| `typecheck` | DSL 用法合法 | 内容对不对 |
| `validate` | 容量装得下、required 事实还在、图表数据自洽、节奏不塌 | 这页该不该存在 |
| `export:pptx` | 能生成 .pptx | 打开好不好看 |
| `verify:geometry` | 网页与 .pptx 每个盒子坐标一致 | 盒子该不该放那儿 |

`validate` 具体会报的错：未知 archetype、容量不足、控件越界、`required` 事实
没出现在渲染结果里、grid 越界、图表序列数/长度不符、序列超过 6 条、
卡片墙超过正文页 1/3、封面不止一个、`deck.meta.theme` 与磁盘上的主题不一致。
警告：文字大概率溢出、相邻页同 family、多序列没图例、饼图切片过多、
一页只有一个方案。

## 人管什么

四道机器校验全绿之后，**渲染截图逐页看**，按六个维度判断：

1. **目标一致性** —— 这份稿子回答了用户要回答的问题吗？重点、结论、语气
   适合这批听众吗？
2. **内容覆盖** —— 指定的要点、页数、语言、图表都落实了吗？有没有跑题页、
   有没有残留的模板默认文案？
3. **逐页成立** —— 每页只讲一件事吗？标题、数据、图表、结论互相印证吗？
   有没有空页、断层、明显不匹配的版式？
4. **方案质量** —— v1~v3 共享同一批事实和关键数字吗？整稿有没有循环同一组
   三布局？v4 是**基于同一事实源重新组织表达**，还是前三个的小改？它的几何
   看得出它声明的 compositionFamily 吗？
5. **叙事完整** —— 开场、展开、结论的顺序清楚吗？页与页之间有承接吗？
6. **交付完整** —— 文件能打开吗？页数对吗？字体在别人机器上会怎样？

## 三态

结论只有三个，不许有第四个：

| 状态 | 含义 | 接下来 |
|---|---|---|
| **通过** | 六个维度都成立 | 交付 |
| **待修正** | 具体某几页不达标 | **只改那几页**，重渲染，只复验这几页 |
| **阻塞** | 缺信息 / 素材 / 决策，改不动 | 停下来，明确说缺什么 |

「待修正」的关键是**最小切片**：不重选模板、不重写其余页面、不重复整稿视觉
检查。一次返工只碰失败的那几页。

## 一条铁律

拿到自检结论后**先按 fail 项把产出改完**，再向用户汇报「做完了 + 结论 +
改了什么」。**直接把原始结论丢给用户但不修复 = 违规。**

## 视觉目检为什么不可省

配色、字重、装饰层、图形是否被遮挡 —— 这几类问题 code review 一定看不出来。
开发这套东西时，目检抓到而 review 全部漏掉的真实缺陷：

- 主题的发丝网格被页面背景整块盖住（签名装饰消失）
- 标题字重写死 600，无视了主题「越大越细」的 200 签名
- 饼图楔形被三次曲线拉成花瓣（环形图正常，所以只有饼图坏）
- `--chart-neg` 的 CSS 与 JS 公式不一致（60% vs 0.5）
- metric 数字不随框宽收缩，两个指标叠在一起
- 时间线节点标记占满整格（应该是 12px 的刻度）
- **CSS 导入顺序反了，网页用兜底配色、导出器用主题配色**

最后一条尤其说明问题：两个渲染器各用一套颜色，所有机器校验全绿。
